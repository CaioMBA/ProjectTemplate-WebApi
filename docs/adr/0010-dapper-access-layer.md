# 10. Hand-rolled Dapper access layer instead of Dapper.Contrib

Status: Accepted

## Context

The template needs raw SQL alongside EF Core: stored procedures, streaming reads, multiple
result sets and cheap single-table CRUD.

Dapper.Contrib was the obvious candidate and was rejected. It has had no release since
November 2020, has no `[Column]` attribute so it cannot express snake_case columns, and its
key-column handling bypasses the `ISqlAdapter` hook that would otherwise let a caller fix
that.

## Decision

`ISqlDatabaseAccess` is a Domain port covering query, scalar, execute, stored procedures,
`IAsyncEnumerable` streaming, `QueryMultiple` through `ISqlResultSets`, cached paging,
single-table CRUD and transactions with savepoints. It replaced `IReadDbConnection`, which
was deleted.

No Dapper type appears in Domain. The only external types on the port are `System.Data`'s
`IDbTransaction` and `CommandType`.

CRUD SQL is generated by `SqlEntityMapFactory`, which reads EF Core's own `IModel` first.
Snake_case column names and owned-type columns such as `price_amount` and `price_currency`
come free because EF already knows them. Types EF does not map fall back to convention plus
`[SqlTable]`, `[SqlColumn]`, `[SqlKey]` and `[SqlIgnore]`.

## Cached page streaming

`CachedPageStreamer` serves pages from the distributed cache, then warms the remaining
pages once per query key in the background.

The reference implementation this was modelled on used a fire-and-forget `Task.Run` that
captured scoped services and the caller's transaction. Both outlive the request. This
version opens a fresh DI scope with its own connection, links cancellation to
`IHostApplicationLifetime.ApplicationStopping` rather than the request token, caps the work
at `MaxCachedPages`, and shares one in-flight stream between concurrent callers through a
per-page `TaskCompletionSource`.

When the caller supplies a transaction, background warming is disabled entirely and the
read falls back to bounded inline streaming. A transaction cannot outlive its caller.

## Consequences

- One more thing to maintain, in exchange for no abandoned dependency and correct column
  mapping.
- `SqlRowReader.For<T>()` exists because Dapper's `reader.GetRowParser<T>()` only works for
  POCOs; for a scalar `T` it returns an object-returning delegate and the cast throws.
